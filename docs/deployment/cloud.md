# Cloud Topology & Cloudflare Deployment

Canonical production runtime: **Cloudflare Worker** (Nitro preset
`cloudflare-module`). Managed Lovable Cloud deployment uses this same output.

## Build contract (verified against a real build)

| Item                    | Value                                                    |
| ----------------------- | -------------------------------------------------------- |
| Build command           | `bun run build` (`vite build`)                           |
| Output directory        | `dist/`                                                  |
| Worker entrypoint       | `dist/server/index.mjs` (ESM module with `fetch` export) |
| Static assets           | `dist/client` (bound as `ASSETS`)                        |
| Generated Worker config | `dist/server/wrangler.json`                              |
| Nitro preset            | `cloudflare-module`, `nodeCompat: true`                  |
| Preview command         | `npx wrangler --cwd ./dist dev`                          |
| Deploy command          | `npx wrangler --cwd ./dist deploy`                       |

`dist/server/wrangler.json` is generated by the build; it sets `main`,
`compatibility_date`, the `ASSETS` binding pointing at `../client`, and
`no_bundle: true`. Do not hand-edit it and do not commit a competing root
`wrangler.toml` — the generated file is the source of truth.

No extra Cloudflare bindings (KV, D1, R2, Durable Objects, Queues) are used by
the application; database, auth and storage are the managed backend reached over
HTTPS. Nothing else needs to be provisioned.

## Deploy sequence

```bash
bun install --frozen-lockfile
bun run build                       # VITE_* must be present at build time
npx wrangler --cwd ./dist deploy    # requires CLOUDFLARE_API_TOKEN + account id
```

Server-side variables are set as Worker secrets (`wrangler secret put NAME`) or
in the managed platform's secret store — never in the repository. See
[environments.md](./environments.md).

On the managed Lovable Cloud path none of this is run by hand: publishing builds
and deploys the same Worker output and injects the backend/AI variables.

## Topology

```
            ┌──────────────────────────────┐
  Browser ──►  Cloudflare edge             │  static assets (ASSETS binding)
            │  + Worker (SSR, server fns)  │
            └──────────────┬───────────────┘
                           │ publishable / bearer token (RLS enforced)
            ┌──────────────▼───────────────┐
            │  Managed backend             │
            │  Postgres · Auth · Storage   │
            └──────────────┬───────────────┘
                           │ scheduled jobs (pg_cron + pg_net)
            ┌──────────────▼───────────────┐
            │  Warehouse / BI artefacts    │
            └──────────────────────────────┘
```

- **Compute** — SSR and server functions run on workerd. Native Node-only
  modules are unavailable; all dependencies are bundled at build time.
- **Data** — Postgres with row-level security on every public table, scoped by
  the `has_role`, `is_staff`, `owns_student`, `my_company_id` and
  `student_applied_to_me` security-definer helpers.
- **Storage** — private `resumes` bucket; owners read their own files and
  recruiters read only files of candidates who applied to their jobs.
- **AI** — requests go through the gateway using `LOVABLE_API_KEY`; every call
  is metered into `ai_usage_logs`.
- **Auditing** — privileged actions are written to `audit_logs`, readable only
  by placement officers and admins.

## Probes

| Path                                  | Purpose                                           |
| ------------------------------------- | ------------------------------------------------- |
| `/health`, `/api/public/health`       | liveness — application + configuration            |
| `/readiness`, `/api/public/readiness` | readiness — configuration + database reachability |

`200` = healthy/ready, `503` = unhealthy/not ready. Payloads carry only status,
component names, latency and a request id — no secrets, connection strings,
environment values or stack traces. Point uptime monitors at the
`/api/public/*` pair (unauthenticated by contract).

## Self-hosting

Not supported — see [docker.md](./docker.md) for the rationale and the path to
add a separate Node target if it is ever required.

## Scaling notes

- The Worker holds no session state — no sticky sessions, scales per request.
- Read-heavy dashboards rely on the Sprint 13 index migration.
- Warehouse rebuilds (`bun run data:build`) are batch jobs; run them out of
  band, never in the request path.
